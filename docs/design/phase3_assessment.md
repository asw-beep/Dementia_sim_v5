# Phase 3 — assessment mode: scope

The first *consumer* of the simulator. A caregiver interviews a patient without being
told her severity, commits to a CDR, and the system reveals the actual one — and
explains, per domain, what the interview showed and why. Phases 1 and 2 are complete
and signed off; this document scopes Phase 3 before any of it is built.

## Why this was deliberately last

The roadmap has said it since Phase 2 began: **a simulator built alongside its own
scorer gets tuned until the scorer is happy, which proves nothing.** The four patients
were built first and each validated by hand against a live model. Assessment now
arrives as a reader of finished work, and it must stay a reader: nothing in Phase 3
may reach back and adjust the simulator to make its own reports tidier.

## The central thesis: the reveal is a replay, not a judgment

Phase 3 needs almost no new evidence, because every mechanism already explains
itself, per turn, in the trace the session log persists:

- a withheld memory carries its reason and its arithmetic (`WithheldMemory`: cue,
  age, reach vs threshold — or "disoriented to place", or "connected to a memory
  that did not come to mind");
- gist and hedged recalls are flags on the retrieved memory;
- the fade, the overrun, word-finding, and the place gate each append a note with a
  stable prefix — `working memory:`, `word-finding:`, `orientation:` — to
  `trace.reason`;
- the orientation and insight frames are pure functions of the profile, so what she
  was *told about her own clock* on any turn is reconstructible from the profile
  alone.

So the reveal is **an aggregation of the session log, by rule** — never a model's
opinion of the transcript. The invariant extends to the new package:
`assessment/` may not import `personasim.llm`, for exactly the reason
formation may not: an explanation generated by a model would vary between two
readings of the same session, and could be wrong. The report must be right by
construction, or Phase 3 inherits none of the trust Phases 1–2 earned.

**And the system never diagnoses.** The actual CDR is not computed from the
transcript — it is *known*, because it is the profile that was loaded. Assessment
reveals and explains; it never infers. A system that inferred severity from evidence
would be a second scorer to tune the simulator against, which is the exact failure
the phase ordering exists to prevent.

## The honesty boundary: report only what a conversation can show

The CDR instrument rates six domains. The simulator expresses three, and the report
must say so rather than paper over it — the mirror of "a parameter nothing reads is a
lie in a config file":

| CDR domain | Expressed by | Reported? |
| --- | --- | --- |
| Memory | recall gate, working-memory fade | yes — the richest evidence |
| Orientation | the clock (time), the place gate, the person axis | yes |
| Judgment & problem solving | only the long-question overrun | yes, as far as it goes — and the report names the limit |
| Community affairs | nothing | named as unobservable in conversation |
| Home & hobbies | nothing | named as unobservable |
| Personal care | nothing | named as unobservable |

Language (word-finding, the simplified register) is not a CDR domain but is
observable and diagnostic, so it is reported as supporting evidence.

A clinician rates the unobservable domains from an informant interview, not from the
patient — a conversation-only simulator structurally cannot show them. Saying that
plainly in the reveal is what keeps the report clinical rather than cosmetic.

## Sprint 3A — the evidence ledger (`persona assess`)

Aggregation first, blind flow second: the report has to exist and read clinically
sane before anything is worth hiding.

`persona assess <session-id>` (and `--list` to find sessions, mirroring
`persona trace`) reads one session's logged turns and produces a per-domain report:

- **Memory** — recall probes counted by fate (crisp / hedged / gist / withheld),
  remote vs recent split out, each with turn references; delayed-recall behaviour
  read from the fade notes. The preserved-remote / impaired-recent dissociation is
  the headline, because it is what separates the middle stages.
- **Orientation** — what the profile withheld from her frame (weekday, date, place,
  person), and the turns where it showed.
- **Judgment (partial)** — overrun notes: how many multi-part questions collapsed,
  and to how much.
- **Language** — word-finding count and cadence across the session.
- **Unobservable domains** — the fixed statement of what a conversation cannot show.
- Each line of evidence names its turn, so `persona trace` is the drill-down.

The report also states the loaded profile (this sprint has no blindness yet) and,
beside each domain, what the profile's own numbers *intended* — recall thresholds,
fade span, overrun probability — so intended and observed sit side by side. That gap
is Phase 3's whole product, and 3A builds it for a reader who can see everything.

**Deliberately not in 3A:** no prediction capture, no web UI change, no severity
inference, no LLM anywhere, no new trace fields (see open decisions), no persistence
of the report (it is derived — rerunning is free and always current).

**Exit criteria.** `make check` green with the new invariants (no `llm` import in
`assessment/`; the note-prefix vocabulary pinned by test so a reworded note cannot
silently orphan the parser). A healthy session reports "nothing impaired was
observed" and no impairment vocabulary. The 15-probe comparison script re-run at
each severity produces reports a reader can check against the published comparison
artifact — every failure in the transcript accounted for, with its mechanism and its
turn. Driven by hand before the tests are written, as every stage has been.

## Sprint 3B — the blind interview and the reveal

The flow Phase 3 is named for:

1. **Blind session.** Assessment mode serves a session whose profile is hidden: the
   profile label, `/api/profile`, and — critically — the per-message `why?` trace
   panel are suppressed, because the trace names withheld memories and reasons and
   is therefore the answer key. The transcript is all the caregiver gets, which is
   all a clinician gets.
2. **Commitment.** The caregiver commits to a CDR (0, 0.5, 1, 2, 3) before anything
   is revealed. A prediction that can be revised after a peek is not a prediction.
3. **Reveal.** Actual profile, the caregiver's answer beside it, and the 3A report —
   now framed as the *gap*: for each expressible domain, what the evidence showed,
   what the predicted stage would have shown instead (drawn from the profiles as
   data and the `CDR*.md` specs as fixed text), and where the difference was visible
   in the transcript.

Profile selection stays manual in 3B (whoever sets up the session chooses it;
`./run start cdr1` already does this) — random, hidden-by-construction patients are
Phase 4, and 3B must not grow a half-version of them.

**Exit criteria.** A blind session end-to-end in the browser: interview, commit,
reveal. The trace panel demonstrably absent in blind mode and intact outside it. The
one success criterion, judged by a drive: **a person who interviews blind and then
reads the reveal can say, in the transcript's own words, why the actual stage is
what it is** — whether or not their prediction was right.

## Not in Phase 3 — do not build these

- **Scoring the caregiver** — no grades, no accuracy statistics, no leaderboard. The
  reveal explains; it does not mark homework.
- **Severity inference from transcripts** — see above; it is the anti-goal.
- **LLM-written summaries** of the session, however fluent — same rule as formation.
- **Random or generated patients** — Phase 4. **Progression** — Phase 5.
- **New symptoms, mechanisms, or profile fields.** If a drive shows a mechanism is
  needed, it is a Phase 2 amendment argued with a transcript, not a Phase 3 feature.
- **Multi-session assessment.** One interview, one session, one report. Longitudinal
  reads arrive with Phase 5, which is built for them.

## Open decisions (recommendations made; say so if they should go the other way)

1. **Trace notes stay strings, parsed by pinned prefix.** The alternative — a
   structured note object on `MemoryTrace` — touches a Phase 1 model for a consumer
   that four stable prefixes already serve. Recommendation: parse `working memory:`,
   `word-finding:`, `orientation:`, and the recall-gate phrases; pin the vocabulary
   with tests on both sides (impairment emits it, assessment parses it) so a
   reworded note breaks loudly. Revisit only if parsing proves brittle in practice.
2. **The reveal's per-stage expectations come from the profiles and the `CDR*.md`
   specs, not a new expectations file.** The YAML numbers are already the intended
   behaviour; the specs are already the clinical ground truth. A third artifact
   would drift against both.
3. **CLI first, web second.** 3A is CLI-only; 3B adds the web flow. The instrument
   gets built and driven before the presentation layer, as `persona chat` was built
   before `persona serve`.
